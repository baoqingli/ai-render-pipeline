# 根本需求定义

> 需求日期：2026-08-25（原文标记 `260825`）
> 本文档是项目的需求源头。所有技术方案、模块设计、路线规划均以本文档为准，
> 技术方案见 [V1 方案](./cad-to-render-pipeline.md) 与 [V2 可实施方案](./cad-to-render-pipeline-v2.md)。

---

## 需求原文

> **将带矢量信息的 AutoCAD 平面（带平面布置及层高信息）作为基础框架，
> 通过文字描述及参考图，生成空间效果图。**

---

## 需求解读

这句话定义了系统的本质——**三类输入，一个转换，一类输出**：

```
AutoCAD 矢量平面（结构框架）
        +
文字描述（风格意图）
        +
参考图（视觉参照）
        ↓
   空间效果图（输出）
```

核心分工原则由需求直接推导得出：

| 职责 | 由谁保证 | 说明 |
| --- | --- | --- |
| **空间是什么样** | CAD（结构、尺寸、布局、层高） | AI 不得改变 |
| **空间看起来什么感觉** | 文字描述 + 参考图（风格、材质、氛围） | AI 负责呈现 |

---

## 交互模型：输入层 + 全自动流水线 + 结果层反馈

用户只做两件事：**在输入层提供素材，在结果层看图反馈**。
中间的生成流程（解析 → 结构化 → 白模 → 渲染）由程序**全自动**完成，
**中途不设置任何确认环节**。

```
【输入层】用户提供：AutoCAD 平面图（必须）+ 文字描述（必须）+ 参考图（可选）
  ↓
【全自动流水线】解析 / 结构化 / 白模 / 渲染
               （失败用默认值兜底，全程无人工介入）
  ↓
【结果层】用户看图
  ├─ 满意     → 下载
  └─ 不满意   → 回到输入层：修改文字描述 / 更换参考图 → 重新生成（闭环）
```

用户职责边界：

| 层 | 用户做什么 |
| --- | --- |
| **输入层** | 只负责提供 AutoCAD 平面图、参考图、文字描述，不做选择、确认、填参 |
| **流程层** | 零参与，全自动 |
| **结果层** | 看图；不满意时通过**修改输入**（文字描述 / 参考图）驱动下一轮，不直接操作中间产物 |

工程含义：

- 自动解析失败时用**默认值兜底**（如层高 2800mm、墙厚 200mm），流程不中断、不弹确认
- 用户的修正意图只通过**文字描述和参考图**进入系统，由 AI 提取层转化为参数调整
- "确认 / 微调"类 UI 不进入主流程
- 边界要诚实：文字 / 参考图反馈闭环解决的是**视觉风格**问题；
  **结构性解析质量**（墙识别错、门窗漏识别）是系统自己的责任，只能靠自动解析能力提升解决，
  无法靠用户在结果层反馈修正——这抬高了自动解析（V2 Phase 3）的优先级

## 输入定义

### 输入 1：带矢量信息的 AutoCAD 平面（必须）

| 要素 | 定义 | 工程含义 |
| --- | --- | --- |
| **矢量信息** | 图纸由可解析的几何图元构成（线段、多段线、块、图层、文字标注），而非图片或扫描件 | 程序可直接读取（DXF/DWG 解析），不需要视觉识别 |
| **平面布置** | 图中可能包含家具、洁具等布置信息 | 有布置信息时**以 CAD 为准**，AI 不改动；无布置信息且需要布置时，由 **AI 合理补全**，底线是**布局合理**（尺度、动线、朝向），不是自由发挥 |
| **层高信息** | 图中携带层高标注 | 优先从图纸文字标注自动提取；缺失时用默认值兜底（如 2800mm），流程不中断 |

对 CAD 输入的明确要求（来自需求中"矢量"一词）：

- 必须是 DXF / DWG 等矢量格式：几何以**坐标数据**直接存在文件里（墙 = 一段带端点
  坐标的多段线），程序读取即精确，完全确定
- 图片 / 扫描件不满足要求：几何以**像素**呈现，图上的长度标注也只是像素组成的字形。
  程序必须先"看懂图"（找线 / OCR 认标注 / 定比例 / 纠畸变），每步都是概率性识别，
  错误会传导进白模和渲染图，且在全自动闭环下用户无手段修正
  ——标注文字只描述"某两处之间多长"，不提供墙在哪里 / 门窗开在哪，几何本身仍需从像素猜测
- PDF 分两种：**CAD 导出的矢量 PDF**（内部仍是绘图指令）可转回 DXF，属有损可行
  （图层名 / 块名常丢失），可作后续扩展；**扫描 / 截图型 PDF** 等同于图片
- 图片输入若将来要支持，需要一条独立的"图纸识别流水线"（CV 找线 + OCR +
  LLM 辅助理解），输出与 DXF 解析相同的结构 JSON——准确率是概率性的，
  与 DXF 解析的确定性不在一个量级，因此列为后续扩展而非主流程
- 图元落在可识别的图层上（墙体、门窗、布置、标注）
- 单位明确（mm 或 m）

### 输入 2：文字描述（必须）

用户用**自然语言**描述风格意图（"温馨的日式原木风，暖光，木地板"），
不要求用户懂设计分类、不填表单——与需求原文"通过文字描述"直接对应。

后台加一层 **AI 大模型提取**，把自然语言转成结构化风格参数，
再由**确定性模板**拼装成专业稳定的渲染 prompt：

```
用户自然语言描述（低门槛输入，怎么说都行）
  ↓ LLM 结构化提取（输出受 Schema 约束，字段缺失取默认值）
风格参数 JSON（style / floor / wall / light / budget ...）
  ↓ 确定性模板拼装（不是 LLM 直接写渲染 prompt）
稳定专业 prompt（正面 + 负面）
  ↓
ComfyUI 渲染
```

设计要点：

- **输入门槛低**：自然语言 + 参考图是仅有的用户输入，无表单、无中途参数确认
- **LLM 只做提取，不写最终 prompt**：提取结果受 Schema 约束（枚举字段校验），
  渲染 prompt 由确定性代码从参数拼装，保证批量生成的一致性和稳定性
- **修改即重新描述**：对结果不满意时，追加 / 修改文字描述或更换参考图触发重新
  生成，不调参数表单
- **解析不了的要兜底**：LLM 无法识别的风格意图按默认值出图，由用户在下一轮
  结果反馈中用补充描述覆盖，不中断流程、不弹窗询问

### 输入 3：参考图（可选增强）

用户提供风格参照图片，通过 IP-Adapter 等机制控制视觉风格，权重需可控（建议 0.6 - 0.8），
保证参照风格的同时不破坏 CAD 决定的结构。

---

## 输出定义

**空间效果图**：与 CAD 平面在几何上严格对应的空间渲染图。

具体产品指标（沿用的 MVP 口径）：

- 每个房间 2-4 个视角
- 每个视角 3-6 张风格变体
- 支持收藏、重生成、下载
- 结构（墙体位置、门窗洞口、家具布置、层高比例）与 CAD 一致，不因 AI 渲染而变形

---

## 隐含约束（从需求推导的验收边界）

1. **CAD 是结构唯一权威。** 墙体位置、门窗洞口、家具布置、层高均以 CAD 为准；
   AI 渲染不得新增 / 删除门窗、移动墙体、改变布局。
2. **布置优先级：CAD 布置 > AI 补全。** CAD 里有布置时以 CAD 为准，AI 不改动；
   没有时由 AI 补全，但补全发生在**白模层**（生成体块布局，进入 Depth / Lineart
   控制图），而不是让渲染模型靠 prompt 自由发挥——这样布局是显式生成、可控可复现的，
   底线是**布局合理**（尺度、动线、朝向）。
3. **"层高信息"在输入里。** 三维白模的竖向尺寸来自图纸标注，缺失时用默认值兜底
   （默认值是工程常量，不是向用户提问）。
4. **文字描述与参考图只影响视觉层。** 风格、材质、光照、氛围可变；结构不可变。
5. **全程无确认环节。** 解析 → 结构化 → 白模 → 渲染全自动，解析失败用默认值和
   规则兜底，流程不中断；用户的修正意图只通过结果层的文字描述 / 参考图进入。
   这意味着结构性解析质量是系统自己的责任，无法靠用户中途修正。

---

## 验收标准

需求满足的判定条件：

| # | 标准 | 验证方式 |
| --- | --- | --- |
| 1 | 给定一张带布置和层高的 DXF，系统能生成结构正确的三维白模 | 白模图 / 深度图与平面对照 |
| 2 | 门窗洞口位置与 CAD 一致，墙体无明显变形（概率性生成，按批次过滤挑优后交付，不追求逐像素一致） | 渲染结果与平面叠合检查 |
| 3 | CAD 有布置时家具位置一致；无布置时 AI 补全的布局合理（尺度 / 动线 / 朝向） | 目视对照 + 抽查评审 |
| 4 | 同一 CAD + 不同文字描述 / 参考图，产出不同风格效果，但结构不变 | 多风格批次对比 |
| 5 | 层高与图纸标注一致（空间比例正确） | 渲染图竖向比例检查 |
| 6 | 主流程无中途交互：上传后一键到结果 | 全流程走查，无确认 / 填写环节 |

## 与技术方案的对应关系

| 需求要素 | 承接模块（见 V2 方案） |
| --- | --- |
| 矢量平面输入 | CAD 输入模块（ezdxf 解析 DXF，ODA 做 DWG→DXF 转换） |
| 平面布置 | 结构化数据模块（布置图元提取）+ Blender 白模（家具体块）；无布置信息时由 AI 布局补全（白模层生成体块，受布局合理性约束） |
| 层高信息 | CAD 输入模块（标注自动提取 + 默认值兜底）+ 结构化 JSON `floor_height` |
| 基础框架 | Blender 白模模块 + Depth / Lineart 控制图 |
| 文字描述 | LLM 提取层（自然语言 → 风格参数 JSON）+ AI 渲染模块（模板拼装 prompt） |
| 参考图 | AI 渲染模块（IP-Adapter，权重可控） |
| 空间效果图 | AI 渲染模块（ComfyUI / SDXL / ControlNet）+ 结果筛选模块 |
